# Incident log

**One entry per anything-unexpected, on water or on the bench.** Newest last.

"Unexpected" is deliberately broad. It includes things that did no harm, things that turned
out to be operator error, and things that fixed themselves. Those are the entries that
matter later, because the pattern is only visible across several of them — and a log that
only records disasters is a log that never sees one coming.

If it made you say "huh", it goes in.

## Rules

- Write it the same day, before the explanation has settled into a story.
- **What the log showed** is a separate column from **what happened**, on purpose. What you
  saw and what the data says are different claims and they disagree more often than is
  comfortable.
- Record the **tag that was on the boat**. Without it the entry cannot be tied to a code or
  parameter state, and an incident you cannot tie to a state is an anecdote.
- If it produced or should produce an issue, link it. If you decided not to open one, say
  so and say why.
